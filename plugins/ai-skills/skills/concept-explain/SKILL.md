# concept-explain — 동기부터 빌드업하는 개념 설명

## When to use

다음 중 하나에 해당하면 발동:

- 사용자가 `/concept-explain <개념>` 형태로 명시 호출.
- 사용자가 **개념적 깊이**를 요구하는 자연어 질문: "X가 뭐야?", "X 원리 설명해줘", "X 왜 쓰지?", "X 동기 설명".
- 사용자가 직전 응답에 대해 "잘 이해가 안 돼", "더 풀어서 설명해줘" 라고 할 때.

**발동하지 말아야 할 때**:

- 단순 사실 질문 ("X 단위가 뭐야?", "X 값이 얼마야?").
- 코드 작성·디버깅 질문.
- 절차 질문 ("X를 어떻게 해?", "X 명령어 알려줘").

## Inputs

다음 중 하나로 입력 해석:

1. ARGUMENTS에 개념명 명시: `/concept-explain 푸리에 변환`
2. ARGUMENTS 없으면 대화 맥락에서 가장 최근 미해결 개념 추출.
3. 둘 다 없으면 한 줄로 "어떤 개념을 설명할까?" 물은 뒤 대기.

## Pre-writing scan (응답 작성 전 의무)

응답을 쓰기 시작하기 **전에** 다음 절차를 머릿속에서 실행. 이 스캔은 **prereq 누락의 1차 방어선** (이후 0단계 작성 = 정의, 마지막 self-check = 사후 검증으로 3중 방어 완성).

### 절차

1. **용어 인벤토리**: 1~7단계에서 사용할 핵심 기술 용어를 모두 나열.
2. **3분류** (아래 binding criteria 적용):
   - **Elementary** — 정의 불필요.
   - **이미 정의됨** — 0단계 불필요.
   - **새 prereq** — 0단계 후보.
3. 새 prereq ≥ 1 → 0단계 작성. = 0 → 0단계 생략.
4. 새 prereq ≥ 4 → 개념 범위 과대. "X부터 먼저 보자" 한 줄 안내 후 분할 또는 진행.
5. **목표값·정규화 grounding 검사**: 설명할 절차에 정규화 변수의 특정 값, magic number 성공 기준, 또는 차트/공간의 canonical point 가 등장하는가? → 해당 시 본문 (4단계 또는 5단계) 에서 그 값의 물리적 의미를 동치 chain 으로 풀이. 판정 기준은 아래 "Grounding 판정 기준 (binding)".

### 분류 기준 (binding)

LLM이 임의 판단으로 회귀하지 않도록 다음 기준을 **반드시** 적용.

**Elementary 판정** — 다음 두 조건을 **모두** 만족해야 함:

- (a) 해당 도메인 입문 교재의 **1~2장 수준** 개념.
- (b) **한 줄로 정의 가능**.

| 예시 | Elementary? | 이유 |
|---|---|---|
| 전압, 전류, 저항 | O | 입문 1장 + 1줄 정의 |
| 미분, 적분 (기본) | O | 입문 + 1줄 |
| 어드미턴스 | X | 1줄 정의는 가능하지만 입문 1-2장 아님 |
| 푸리에 변환 | X | 입문 후반 + 1줄 정의 불가 |
| 텐서, 군 | X | 1-2장 아님 + 1줄 정의 어려움 |

**이미 정의됨 판정** — 직전 대화에서 **명시적 정의** (수식 `X = ...` 또는 정의 문장 "X는 ~이다") 로 등장한 경우만. **단순 언급·이름 사용·관련 토픽 등장은 불충분**.

예: "임피던스 매칭"이 대화에 나왔다고 해서 "어드미턴스"가 정의된 것은 아님 (전혀 다른 개념). 정확히 그 용어가 정의 형태로 등장했는지 확인.

**Default rule (의심 시)**: 위 둘에 명확히 안 들어가면 → **새 prereq 로 분류**. 정의 1줄 추가하는 비용 ≪ 누락으로 사용자 이해 끊기는 비용. **Over-include 권장**.

### Grounding 판정 기준 (binding)

용어 정의(prereq) 와 **별개의 검사 축**. "그 값/위치가 무엇을 뜻하는가" 를 풀어야 하는지 판정.

**Grounding 필요** — 다음 중 하나 이상 해당 시 본문에서 물리 의미 풀이 필수:

- (a) **정규화 표기 변수의 특정 값**. 소문자 y, z, γ 등이 reference 로 나눈 값을 뜻하는 경우의 등장 값. 예: y=1, z=0, |Γ|=1.
- (b) **절차의 성공 기준 상수**. 예: "목표는 X = K", "수렴 = 0", "최대화 → 1".
- (c) **차트/공간의 canonical point**. 예: 스미스 차트 원점, 단위원, 좌표축 특수점.

**Grounding 불필요** — 다음 중 하나 해당 시 skip:

- 계산 결과로 나온 임의 수치. 예: d ≈ 0.063λ, z_L = 2+j.
- 입력 파라미터 (사용자가 던진 값). 예: 부하 Z_L = 100 + j50.
- 도메인에서 자명한 상수. 예: π 가 단순 각도일 때.

**Default rule (의심 시)**: (a)~(c) 중 하나에라도 살짝 걸치면 → **grounding 적용**. 풀이 2-3줄 비용 ≪ 사용자가 "왜 그 값?" 으로 막히는 비용.

**물리 의미 풀이 형식 — 동치 chain**:

정규화를 풀어쓴 뒤 동치 조건을 chain 으로 연결. **최소 2단계** (정규화 풀이 + 동치 조건 1개) 이상. 1단계 풀이 (예: "y=1 → 매칭") 는 의미 없음.

예시 (한국어 라벨 포함 → 코드블록이 아니라 독립 프로즈 행):

y=1 ⇔ Y=Y_0=1/Z_0 ⇔ Z=Z_0 ⇔ Γ=0 ⇔ 매칭

## Output template — 7단계 흐름

다음 구조를 **순서대로** 따른다. 각 단계는 마크다운 헤더(`## N단계 — ...`)로 명확히 분리.

### 0단계 — 전제 개념 (사전 지식) *(조건부)*

본 설명에서 사용될 비-elementary 용어 중, 사용자에게 아직 정의되지 않은 것들을 압축 제시. **Pre-writing scan 결과 새 prereq ≥ 1 일 때만 작성**.

**형식**: 불릿 리스트, 각 항목 굵은 용어명 + 1~2문장 정의 + (선택) 본 설명에서 왜 쓰이는지.

```markdown
- **용어명**: 한 줄 정의 (수식). (선택) 본 설명에서 왜 필요한지 한 마디.
```

**예시**:
- **어드미턴스** Y = 1/Z: 임피던스의 역수, 단위 S(지멘스). 병렬 회로에서 단순 합산이 가능해 매칭 계산이 깔끔.

**제약**:
- 최대 3개 항목. 4개 이상이면 개념 범위 과대 → 분할 안내.
- 1단계(동기)에 들어가지 않을 정도로 압축 (정의만, 동기/응용은 1~7단계에서).

### 1단계 — 왜 [X]가 필요한가?

문제 상황·필요·맥락. 누가/언제/어떤 상황에서 직면하는지 구체 시나리오 1~2개. 정의를 먼저 던지지 말 것 — 동기가 먼저.

### 2단계 — 어떤 한계/필요/현상을 다루는가?

이 개념이 답하려는 한계, 다루는 현상, 또는 충족시키는 필요. 두 가지 프레임 중 적합한 쪽 선택:

- **Corrective 프레임** (문제 해결형 개념): "안 하면 X% 손실", "안 하면 시스템이 망가짐" — 정량 손해 명시. 예: 임피던스 매칭, 오류 정정 코드.
- **Constructive 프레임** (도구·추상형 개념): "이게 없으면 Y를 표현/측정/분리할 수 없다" — 표현력 한계 명시. 예: 푸리에 변환, 복소수, 엔트로피, 추상대수.

가능하면 정량적 수치 포함하되 강제하지 않음.

### 3단계 — 단순한 해법은 왜 안 통하는가? *(조건부)*

가장 자연스러운 첫 시도와 그 실패 이유. **단순 해법이 명확히 존재할 때만** 포함. 없으면 생략.

예: λ/4 변환기 설명 시 "그냥 같은 Z_0 선로를 길게 쓰면 안 되나?" → "|Γ|가 불변이라 안 됨" 같은 흐름.

### 4단계 — 핵심 통찰 (Aha 포인트)

이 개념의 결정적 아이디어를 **한 문장**으로 압축. 빌드업의 클라이맥스. **이 단계 누락은 skill 실패로 간주.**

### 5단계 — 왜 이 방법이 작동하는가? *(조건부)*

핵심 통찰을 수식·도형·물리적 직관으로 풀어 설명. 수식이 비자명하거나 직관적 그림이 필요할 때 포함.

### 6단계 — 구체적 예시

다음 두 형태 중 개념의 성격에 맞는 쪽 선택 (**둘 다 허용**):

- **수치 워크드 예제**: 회로 계산, 물리 문제, 수치 알고리즘 등 계산 가능 도메인.
- **정성적 미니 케이스 스터디**: 위상수학, 추상대수, 패러다임 비교 등 수치화 어려운 추상 도메인.

추상 개념에 억지로 수치를 넣지 말 것. 정성적 비교 시 표·다이어그램 적극 활용.

### 7단계 — 한 줄 요약

> 전체를 한 문장 인용블록으로 압축. 사용자가 이 줄만 가지고 가도 핵심이 남게.

## Required vs Optional

| 단계 | 필수성 |
|---|---|
| 0 | Pre-writing scan 결과 새 prereq ≥ 1 일 때 |
| 1, 2, 4, 6, 7 | **항상 필수** |
| 3 | 단순 해법이 명확히 존재할 때 |
| 5 | 수식/직관이 비자명할 때 |

## Tone & style

- 대화 언어 매칭 (기본 한국어).
- 캐주얼하지만 기술적으로 정확한 톤. 반말 또는 친근한 존댓말.
- **수식은 평문 표기** (이 환경은 GFM 터미널 — LaTeX 미렌더링, `$...$` 가 날 소스로 그대로 노출됨):
  - 인라인: 구분자 없이 평문. 아래첨자는 언더스코어(`B_L`, `R_l`, `f_p`, `Z_Tp`), 제곱·세제곱은 유니코드 `²`/`³`, 그 외 위첨자는 `^n`.
  - 기호는 유니코드: `ω π μ Ω Γ λ β ℓ γ √ ≈ ≤ ≥ ≠ ⇔ → ↔ · × ∞ ∠`. 허수단위 `j` 와 삼각함수 `sin cos tan cot` 등은 그대로.
  - 분수는 슬래시+괄호: `a/b`, `(R_l² + X_L²)/R_l`. 음수·뺄셈은 ASCII `-` (유니코드 `−` 대신).
  - 블록/전개 수식은 펜스 코드블록(` ``` `)에 평문 레이아웃으로 — 마크다운 간섭 차단 + 시각 분리.
  - 동치 chain(grounding): **순수 기호만 있으면 코드블록**, 한국어 단어(라벨)가 섞이면 코드블록이 아니라 **독립 프로즈 행**에 `⇔` 로. 예) `y=1 ⇔ Y=Y_0 ⇔ Z=Z_0 ⇔ Γ=0 ⇔ 매칭`
  - 드물게 렌더러가 인라인 `_` 를 이탤릭으로 깨면, 그 인라인 수식만 백틱(인라인 코드)으로 감싼다: `` `B_L` ``.
- **LaTeX → 평문 변환표** (출력 전 이 매핑을 적용; LaTeX 잔재 0이 목표):

  | LaTeX | 평문 |
  |---|---|
  | `$x$` / `$$x$$` | 구분자 제거 / 코드블록 |
  | `\dfrac{a}{b}`, `\frac{a}{b}` | `a/b`, `(a)/(b)` |
  | `x^2`, `x^3` | `x²`, `x³` |
  | `\sqrt{x}` | `√(x)` |
  | `\omega \pi \mu \Omega \Gamma \lambda \beta \gamma` | `ω π μ Ω Γ λ β γ` |
  | `\ell` | `ℓ` |
  | `\approx \leq \geq \neq \infty \angle` | `≈ ≤ ≥ ≠ ∞ ∠` |
  | `\Leftrightarrow \to \cdot \times` | `⇔ → · ×` |
  | `\cot \tan \cos \sin` | `cot tan cos sin` (그대로) |
  | `\text{in}`, `x_{\text{total}}` | `in`, `x_total` (첨자는 언더스코어) |
  | `\boxed{...}` | 코드블록 또는 **굵게** |
  | `\;` `\,` `\quad` | 일반 공백 |
  | `X_L`, `R_l`, `j` (허수단위) | 그대로 |

- 비교·대조는 표로. 단, **표 셀에는 짧은 표현만** (스칼라·부호·방향·단어). 분수-합/다항식은 셀에 넣지 말고 표 밖 코드블록·독립 행으로.
- 짧은 문단, 명확한 단계 구분. 한 응답이 과도하게 길어지면(예: 서로 독립적인 두 개념을 한 번에) "X부터 보자" 분할 안내 후 나눠 설명.
- 이모지 금지.

## Prohibitions

- **정의를 먼저 던지지 말 것**. 정의는 4~6단계에서 자연스럽게 등장.
- **공식 나열 금지**. 모든 공식은 동기 설명 뒤에만 등장.
- **단계 건너뛰기 금지**. 특히 `1 → 2 → 4 → 6 → 7` 흐름은 절대 생략 불가.
- **5단계 이하로 압축 금지** (필수 단계만으로도 최소 5개).
- **모든 개념에 corrective 프레임 강제 금지**. "안 하면 나쁘다"가 어색하면 constructive 프레임으로 전환.
- **추상 개념에 억지 수치 예제 금지**. 정성적 예시가 더 정확하면 그쪽으로.
- **비-elementary 용어를 정의 없이 사용 금지**. 본문에서 처음 등장하는 도메인 용어는 0단계 또는 그 자리에서 한 줄 인라인 정의 필수. Pre-writing scan 의 분류 기준에 따라 판정.
- **정규화 목표값·성공 기준·canonical point 를 물리 의미 풀이 없이 사용 금지**. "y=1 이 목표" 라고만 쓰지 말고 동치 chain (y=1 ⇔ Y=Y_0 ⇔ Z=Z_0 ⇔ 매칭) 으로 풀이 동반. Pre-writing scan 의 Grounding 판정 기준에 따라 판정.
- **LaTeX 수식 표기 금지**. `$...$`·`$$...$$` 구분자와 LaTeX 전용 매크로(`\dfrac \frac \sqrt \omega \Gamma \Leftrightarrow \text \; \,` 등)를 출력에 쓰지 말 것. 이 환경(GFM 터미널)은 LaTeX 를 렌더링하지 않아 날 소스가 그대로 노출된다. 위 "수식은 평문 표기" 규약·변환표로 대체.
- **표 셀에 분수·다항 전개식 금지**. 셀에는 짧은 스칼라·부호(+/-)·방향·단어만. 분수-합 형태나 항이 여럿인 수식은 표 밖 코드블록 또는 독립 행으로 빼낼 것.

## Reference example — λ/4 변환기

다음은 본 skill이 재현해야 할 모범 응답의 압축판. 사용자가 실제로 만족했던 흐름. (수식은 모두 평문 표기 — 출력 시 이 형태를 모방할 것.)

### 1단계 — 왜 임피던스 매칭이 필요한가?

소스는 표준 Z_0 = 50 Ω, 부하는 그렇지 않음. 안테나 73Ω, TV 75Ω, 칩 입력 제각각. 둘이 다르면 부하에서 반사 발생:

```
Γ_L = (Z_L - Z_0) / (Z_L + Z_0)
```

### 2단계 — 반사가 어떤 손해를 가져오나? (corrective)

- **전력 손실**: |Γ_L|² 만큼 부하 도달 못 함. Z_L=100, Z_0=50 시 11% 손실.
- **소스 손상**: 반사파가 RF 앰프 출력단 태움.
- **정재파**: 절연 파괴, 측정 부정확.

### 3단계 — 단순한 해법은 왜 안 통하나?

같은 Z_0 선로를 길게 늘여도 |Γ| 는 불변 — 위상만 회전. 부하 임피던스 자체는 변환 안 됨.

### 4단계 — 핵심 통찰

**다른 특성 임피던스의 선로 한 토막을 끼우면** 양 경계에서 두 번 반사가 일어나고, 이 둘이 정확히 상쇄되게 설계 가능.

### 5단계 — 왜 작동?

길이 λ/4 에서 βℓ = π/2, tan(βℓ) → ∞. 선로 임피던스 공식이 깔끔히 정리:

```
Z_in = Z_1² / Z_L
```

임피던스의 **기하평균** 변환.

### 6단계 — 구체적 예시 (수치)

Z_0 = 50 Ω 시스템에 Z_L = 100 Ω 부하 매칭:

```
Z_1 = √(50 × 100) ≈ 70.7 Ω
```

`[50Ω 소스] ════════ [70.7Ω, λ/4] ──── [100Ω 부하]`

→ 소스 쪽에서 보면 부하가 50 Ω 로 보임, 반사 0.

### 7단계 — 한 줄 요약

> 부하 임피던스를 변환해야 하는데 같은 임피던스 선로로는 안 되고, 다른 임피던스 선로 한 토막을 정확히 λ/4 길이로 끼우면 두 경계의 반사가 상쇄돼서 변환이 완성된다.

**비고**: 이 reference 는 **0단계 불필요 케이스**. 사용된 용어(임피던스, 반사, 정재파)가 모두 대화 맥락에서 정의되었거나 elementary 라서 prereq 0개.

## Reference example 2 — 단일 스터브 튜너 (0단계 시연)

본 reference 는 **0단계 발동 케이스**. λ/4 변환기를 학습한 사용자에게 단일 스터브 튜너를 설명할 때 "어드미턴스"·"서셉턴스"가 새 prereq 로 잡혀 0단계가 작동. (수식은 모두 평문 표기.)

### 0단계 — 전제 개념

- **어드미턴스** Y = 1/Z: 임피던스의 역수, 단위 S(지멘스). 병렬 회로에서 단순 합산이 가능해 매칭 계산이 깔끔.
- **서셉턴스** B: 어드미턴스의 허수부 (Y = G + jB). 임피던스의 리액턴스 X 에 대응.

### 1단계 — 왜 단일 스터브 튜너가 필요한가?

λ/4 변환기는 (a) 부하가 순저항일 때만 직접 통하고, (b) 특수 임피던스 케이블이 필요. 그런데 실전 부하는 거의 다 복소수 (안테나, 칩, PCB 라우팅) 이고, PCB 설계 입장에서는 보드 전체를 하나의 Z_0 (50Ω) 만 쓰고 싶음.

### 2단계 — 어떤 한계를 다루는가? (corrective)

복소 부하 Z_L = R + jX 에서:
- λ/4 변환기: Z_1²/Z_L 이 복소가 되어 실수 Z_0 와 같아질 수 없음.
- 같은 Z_0 선로만 연장: |Γ| 불변, 미스매치 그대로.
- 정량: Z_L = 100+j50 → |Γ|² ≈ 0.31 → 31% 손실.

### 3단계 — 단순 해법은 왜 안 통하나?

Lumped 인덕터/커패시터 직렬 추가 → RF 고주파에서 parasitic·자기공진 문제. 같은 Z_0 선로 연장 → |Γ| 불변. → 분포소자만으로 리액턴스 상쇄 방법 필요.

### 4단계 — 핵심 통찰

**끝-단락(또는 끝-개방) 한 같은 Z_0 선로 토막은 순 리액턴스로 동작**. 메인 선로의 적절한 지점에 병렬 분기시켜 잔여 서셉턴스를 정확히 상쇄.

### 5단계 — 왜 작동?

**왜 y=1 이 목표?** 정규화 어드미턴스 y = Y/Y_0 = Y · Z_0. y=1 이라는 건 Y = Y_0 = 1/Z_0, 즉 Z = Z_0 — **정합의 정의 자체**. 동치 chain (한국어 라벨 포함 → 독립 행):

y=1 ⇔ Y=Y_0 ⇔ Z=Z_0 ⇔ Γ=0 ⇔ 스미스 차트 원점 ⇔ 매칭

모두 같은 한 점. 절차의 목표 "y_total = 1" 은 임의 숫자가 아니라 매칭의 정규화 표현.

3단계 절차:
1. 메인 선로 따라 회전 → 어느 거리 d 에서 y(d) = 1 + jb (실수부 = 1) 도달.
2. 그 지점에 어드미턴스 -jb 짜리 스터브 병렬 연결.
3. 합: y_total = 1 + jb - jb = 1 → 정합.

스터브 길이 ℓ 조정으로 임의의 서셉턴스 생성 가능:

```
y_sc = -j·cot(βℓ),   y_oc = j·tan(βℓ)
```

미지수 2개 (d, ℓ), 매칭 조건 2개 → 해 존재.

### 6단계 — 구체적 예시

Z_0 = 50, Z_L = 100 + j50. z_L = 2+j, y_L = 0.4 - j0.2. 스미스 차트에서 y_L 부터 s원 따라 회전, g=1 원과 교점에서:
- d ≈ 0.063λ, 잔여 +j1.0
- 스터브 (단락): ℓ_s = λ/8, 어드미턴스 -j1.0

→ 50Ω 케이블 **한 종류**만으로 매칭 완성.

### 7단계 — 한 줄 요약

> 복소 부하를 한 종류의 Z_0 케이블만으로 매칭하기 위해, 어드미턴스 실수부가 1 이 되는 메인 선로 위 지점을 찾아 그 위치에 끝-단락(또는 끝-개방) 짧은 선로 토막을 병렬 분기해 잔여 서셉턴스를 상쇄하는 분포소자 매칭 기법.
